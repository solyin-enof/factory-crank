# Original game inspiration

Source supplied by the user during the workshop expansion: [Factory Game Design conversation](https://chatgpt.com/share/6ad6e3d8-89c0-83e8-afb7-98ae73d21e2a). Read on 2026-10-19. This is design context, not independent research evidence. Claims about other games and studies inside that conversation are not adopted as verified facts.

The user's original proposal follows iron through transformations, then makes operating a physical mechanism the immediate interaction. The conversation develops a material stream that can become plates, gears and increasingly complex machines. It places the interesting decisions in resource dependencies, routing and which bottleneck to address.

The final discussion distinguishes this from a generic circular-input incremental game: manual operations should become obsolete through automation, earlier machines should keep contributing, and successive mechanisms should behave differently. It treats the crank as one physical input, rather than a resource generator that needs endless upgrades. The runner and two-stream variants were exploratory proposals, not established requirements to replace the current stationary factory.

## Consequences for this expansion
- Keep the original mining/blower/press interactions and keep the factory running after milestones.
- Make the selected material transformation visible: ore, plate, then the active die's actual output.
- Spawn a visual item when production actually completes, rather than only increasing counters.
- Let shared gears/plates become either machinery or the spring/frame branch that assembles into a crawler. That crawler then contributes to the persistent production system.
- Frame the workshop as choosing a useful next form for the iron. Construction clicks allocate stocked components; they do not produce repeated output.
- Springs and frames are alternate dies on the current press. A new gesture for a genuinely different machine remains future work; the expansion does not claim every recipe has a different interaction.

This aligns the implemented expansion with the conversation while retaining the user's later directions: start with less, show machinery gradually, remove hold-to-produce controls, and allow post-gear choices.
